How it works

Seven GitHub sources, one flight plan

No single GitHub response explains a stuck pull request. Maniflight combines the pull request, GraphQL review state, reviews, check runs, commit statuses, hidden Actions runs, and active branch rules, then splits the result into observed blockers and evidence gaps before naming the next actor.

Statuses

Every condition gets an honest label

StatusMeaning
BLOCKEDEvidence identifies a current merge blocker.
ACTIONA person must act before progress can continue.
WAITINGAutomation or another pending condition is not complete.
UNKNOWNThe available evidence cannot support a stronger conclusion.
PASSThe observed condition completed successfully.
INFORelevant, but not known to block the merge.

Automation

One JSON document for your tooling

Add --json for a schema-versioned report with signals, evidence links, next actions, and per-source coverage.

maniflight pr acme/payments-api#218 --json

kind           pull-request-flight
schemaVersion  1.0
outcome        status, next actors, summary
signals        conditions with evidence links
nextActions    who should do what next
collection     source coverage and warnings

Trust

Read-only by design

  • Only GitHub GET requests and GraphQL queries. No comments, approvals, reruns, labels, or merges.
  • No checkout, code execution, log or artifact downloads from the repository it inspects.
  • Missing evidence is reported as unknown, never as a guessed pass.
  • Tokens are read from GH_TOKEN or GITHUB_TOKEN only, and never written to a report.
  • Every report records the observation time and the exact head SHA.

Also included

Repository readiness scan

A second command inspects a repository's architecture, automation, security, and community health without running its code, and writes JSON plus an accessible HTML report. It also ships as a GitHub Action.
